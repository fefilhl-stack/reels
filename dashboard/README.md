# Reels Hub — дашборд коротких видео

Один дашборд для всех ваших проектов: контент-план в том же виде, что и в Google Таблицах,
ролик загружается кнопкой прямо в строке сценария и уходит по API в **TikTok, Instagram Reels
и YouTube Shorts** в дату и время из плана, а статистика собирается сама и превращается
в конкретные рекомендации, что снимать и когда публиковать.

Self-hosted: Next.js 16 + встроенный в Node.js SQLite. Внешних сервисов и баз не нужно, данные
и видео хранятся в папке `data/`.

## Что умеет

**Контент-план — как в Google Таблицах**
- Паспорт проекта повторяет лист «Проекты»: тема аккаунта, обещание зрителю, цель, аудитория, формат,
  длина ролика, норма слов, частота, дата старта, время публикации, обращение, рубрики с долями,
  призывы, на чём основаны факты, чего в роликах нет, где нужна фраза о специалисте, открытые вопросы,
  что проверить перед публикацией.
- Контент-план проекта повторяет лист проекта: №, дата, время, рубрика, тема, хук, обложка, кадр,
  текст озвучки, слов, призыв, подпись, хэштеги, статус, заметки. Ячейки редактируются прямо
  в таблице (Ctrl+Enter — сохранить, Esc — отменить), есть вид «Компактно / Все столбцы», поиск
  и фильтр по статусу.
- Правила шаблона: №1 выходит в дату старта, каждый следующий — в следующий день публикации
  по частоте из паспорта; время — по паспорту (например, 18:00 в будни и 17:00 в выходные).
  «Слов» считается само и подсвечивается, если текст вне нормы. Статусы: Не начат → Озвучен →
  Смонтирован → Опубликован. «Пересчитать даты» заново раскладывает план после смены частоты
  или даты старта.
- Импорт из Google Таблиц (вставкой, по ссылке или файлом CSV) и экспорт обратно: «Копировать
  в Таблицы» и CSV. Подробнее — в разделе [«Перенос из Google Таблиц»](#перенос-из-google-таблиц).
- Страница сценария: все поля плана, счётчик слов против нормы, длительность ролика против паспорта,
  шаблоны хуков, призывов и наборов хэштегов, переход к соседним номерам.
- «Сделать часть 2» — продолжение залетевшего ролика встаёт в конец плана.
- Календарь по датам плана: перетаскивание переносит дату сценария (и уже запланированную публикацию),
  отдельно — ближайшие сценарии без ролика.

**Публикация**
- Кнопка **«Загрузить»** в строке сценария (или перетащите файл на строку): ролик привязывается
  к сценарию, статус становится «Смонтирован», длительность сверяется с паспортом.
  **«Ролики по номерам»** — загрузка пачки файлов с номером сценария в названии (`12.mp4`, `12 тема.mov`).
  Длительность, разрешение и обложка определяются в браузере, а если браузер не смог прочитать
  файл — на сервере через ffprobe/ffmpeg (если установлены).
- Время публикации берётся из плана: **«В публикацию 12.10 18:00»** ставит ролик во все подключённые
  аккаунты проекта, **«Запланировать загруженные»** — все загруженные ролики с будущей датой разом.
  Перенесли дату в плане или в календаре — запланированная публикация переедет за ней.
- Подписи под каждую площадку: собираются из подписи сценария, призыва и хэштегов,
  со счётчиками лимитов (2200 символов, 30 хэштегов в Instagram, заголовок YouTube до 100 символов).
- Настройки площадок на странице сценария: видимость и разрешения TikTok (по данным `creator_info`,
  как требует TikTok), раскрытие рекламы и ИИ-контента, «показывать в ленте» для Reels, доступ
  и «для детей» для YouTube; можно выбрать другое время или опубликовать сразу.
- Фоновый планировщик внутри сервера: публикует по расписанию, отслеживает обработку на площадке,
  делает до трёх повторов при сетевых ошибках, после перезапуска не публикует ролик дважды.
- Выбор обложки по кадру, проверка файла на требования каждой площадки.

**Аналитика**
- Просмотры, лайки, комментарии, репосты, сохранения, досмотр; снимки статистики по времени,
  поэтому видно, как ролик набирал просмотры.
- **«×» — сравнение с обычным для аккаунта.** Просмотры ролика делятся на медиану просмотров
  других роликов этого же аккаунта *в том же возрасте*. Так TikTok, Instagram и YouTube
  становятся сравнимыми, а свежий ролик можно оценить уже через пару часов.
- Рубрики, длительность, лучшее время публикации (тепловая карта день × время), хуки роликов-лидеров,
  сравнение ролика по площадкам, рост подписчиков, выполнение контент-плана.
- По столбцам плана: какой призыв работает (сохранения, репосты, комментарии на «Сохранить»,
  «Отправить», «Комментарий»…), сколько слов в тексте у роликов, которые заходят лучше,
  и доли рубрик в плане против долей из паспорта.
- Импорт последних роликов из подключённого аккаунта — аналитика полная с первого дня.

**Рекомендации («Что сделать»)** — правила, которые смотрят на рычаги роста:
- на ближайшие 3 дня по плану нет загруженного ролика / ролик загружен, но не запланирован /
  пропуск по плану / контент-план скоро закончится / тексты вне нормы слов / не озвучено на неделю вперёд;
- ролик залетел (≥ 2× к обычному) — перенести на площадки, где его ещё нет, и снять продолжение;
- рубрика тянет или проседает, лучшее окно публикации, лучшая длительность, перекос площадок;
- темп роста отстаёт от цели по подписчикам;
- токен истекает, аккаунт нужно переподключить, публикация не прошла.

**ИИ-помощник (необязательно, Claude)** — если задан `ANTHROPIC_API_KEY`: пишет сценарий по паспорту
проекта (хук, обложка, кадр, текст озвучки в норме слов, призыв, подпись, хэштеги и что проверить),
дописывает пустые поля строки плана, даёт 6 вариантов хука, подписи под каждую площадку и темы новых
роликов на основе того, что уже залетело и что провалилось. Цифры и факты берёт только из раздела
паспорта «На чём основаны факты», а если их не хватает — пишет без них и отмечает, что проверить.
Темы добавляются в конец плана одной кнопкой.

## Быстрый старт

Нужен **Node.js 22.13+** (используется встроенный `node:sqlite`).

```bash
cd dashboard
npm install
cp .env.example .env     # можно ничего не менять для первого запуска
npm run dev              # http://localhost:3100
```

На пустом дашборде можно сразу перенести свои Google Таблицы (см. ниже) или нажать
**«Загрузить демо-данные»**: появятся три проекта с паспортами, контент-планами и историей
публикаций за 5–8 недель. Демо-аккаунты публикуют мгновенно и без сети, так что можно пройти
весь путь — сценарий → ролик → публикация по плану → статистика → рекомендации — до получения
ключей. Удалить демо можно в «Настройках».

Продакшен:

```bash
npm run build
npm start                # порт 3100
```

Предупреждение `ExperimentalWarning: SQLite is an experimental feature` в консоли безопасно.

## Перенос из Google Таблиц

«Контент-план» → **«Импорт из Google Таблиц»**. Сначала перенесите лист **«Проекты»** — появятся
проекты с паспортами (дата старта, частота, время публикации, нормы, рубрики с долями, призывы).
Затем по очереди каждый лист с контент-планом проекта.

Три способа:
- **Вставить** — откройте лист, Ctrl+A и Ctrl+C (на Mac ⌘A, ⌘C), затем Ctrl+V в окне импорта.
  Работает и для закрытых таблиц.
- **По ссылке** — ссылка на лист (с `gid=…` в адресе). Таблица должна быть открыта:
  «Настройки доступа → Все, у кого есть ссылка → Читатель».
- **Файл CSV** — в Таблицах «Файл → Скачать → CSV».

Перед импортом видно, что распознано: тип листа, число проектов или сценариев, столбцы и примеры тем.
Столбцы узнаются по названиям, порядок не важен; столбцы, которых нет в шаблоне, попадают в «Заметки». Даты понимаются
в виде `08.10.2026`, `2026-10-08` или числом из Таблиц, время — `18:00` или `18:00:00`. Если у строки
нет даты, она встаёт в следующий день публикации, а пустое время берётся из паспорта.

Повторный импорт того же листа обновляет сценарии с теми же номерами и добавляет новые; загруженные
ролики и публикации он не трогает, а статус ролика, опубликованного из дашборда, не откатывает.
Так можно продолжать писать сценарии в Таблицах и время от времени переносить их.

Обратно: **«Копировать в Таблицы»** кладёт план в буфер обмена — вставьте его в лист через Ctrl+V;
**CSV** — скачать файлом (`GET /api/export?project=ID&format=csv`).

## Подключение площадок

В `.env` укажите `APP_URL` — адрес, по которому открыт дашборд. Из него строятся redirect URI,
которые нужно прописать в консоли разработчика каждой площадки:

```
${APP_URL}/api/oauth/tiktok/callback
${APP_URL}/api/oauth/instagram/callback
${APP_URL}/api/oauth/youtube/callback
```

**TikTok и Instagram не принимают `http://localhost`.** Для них нужен публичный https-адрес:
сервер с доменом или туннель (`cloudflared tunnel --url http://localhost:3100`, `ngrok http 3100`).
Instagram к тому же сам скачивает видео по подписанной временной ссылке с вашего дашборда.

Подробные шаги и актуальный статус ключей — на странице **«Аккаунты»** в дашборде.

### TikTok
1. [developers.tiktok.com](https://developers.tiktok.com/apps) → приложение → продукты **Login Kit**
   и **Content Posting API** (включить Direct Post).
2. Scopes: `user.info.basic`, `user.info.profile`, `user.info.stats`, `video.publish`, `video.list`.
3. `.env`: `TIKTOK_CLIENT_KEY`, `TIKTOK_CLIENT_SECRET`.
4. **Ограничения до аудита TikTok:** публикация только с видимостью «Только я» (SELF_ONLY),
   аккаунт должен быть приватным, до 5 пользователей в сутки. Публичные посты — после аудита
   приложения. Статистику TikTok отдаёт только по публичным роликам.
   Кнопки «В публикацию» и «Запланировать загруженные» в контент-плане ставят TikTok-публикации
   с видимостью «Только я»; другую видимость выбирайте на странице сценария.

### Instagram
1. [developers.facebook.com](https://developers.facebook.com/apps) → приложение (тип Business) →
   продукт Instagram → **API setup with Instagram login**.
2. Разрешения: `instagram_business_basic`, `instagram_business_content_publish`,
   `instagram_business_manage_insights`. Аккаунт — профессиональный (бизнес или автор).
3. `.env`: `INSTAGRAM_APP_ID`, `INSTAGRAM_APP_SECRET` (это Instagram App ID/Secret из настроек продукта).
4. До App Review подключаются только аккаунты, добавленные в роли приложения.
   Лимит — около 100 публикаций через API в сутки на аккаунт; Reels от 3 с до 15 мин, до 300 МБ.
5. Долгоживущий токен (60 дней) обновляется автоматически.

### YouTube
1. [Google Cloud Console](https://console.cloud.google.com/apis/credentials): включите
   **YouTube Data API v3** и **YouTube Analytics API**, создайте OAuth client «Web application».
2. Scopes: `youtube.upload`, `youtube.readonly`, `yt-analytics.readonly`.
3. `.env`: `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`.
4. Переведите OAuth consent screen в **In production** — в режиме Testing refresh-токены живут 7 дней.
5. **Пока проект не прошёл аудит YouTube API, загруженные через API ролики будут приватными.**
   Квота по умолчанию — 100 загрузок в сутки. Shorts — вертикальные/квадратные ролики до 3 минут.

После подключения нажмите **«Импорт роликов»** у аккаунта, чтобы подтянуть последние публикации.

## Развёртывание

Дашборду нужен постоянно работающий Node.js-процесс (планировщик живёт внутри сервера)
и диск для `data/`. Подойдёт любой VPS:

```bash
npm ci && npm run build
DASHBOARD_PASSWORD=... APP_URL=https://reels.example.com npm start
```

Держите процесс живым через systemd или pm2 (`pm2 start npm --name reels -- start`)
и поставьте перед ним nginx/Caddy с https. **Обязательно задайте `DASHBOARD_PASSWORD`**
перед тем как открывать дашборд в интернет, и делайте резервные копии папки `data/`
(`reels.db` и `uploads/`).

Если постоянного процесса нет, выключите встроенный планировщик (`WORKER_ENABLED=false`) и
вызывайте `GET /api/cron?secret=$CRON_SECRET` раз в минуту внешним кроном.

## Переменные окружения

| Переменная | Зачем |
| --- | --- |
| `APP_URL` | Публичный адрес дашборда (redirect URI, ссылки для Instagram) |
| `DASHBOARD_PASSWORD` | Пароль входа. Пусто — без пароля (только локально) |
| `APP_SECRET` | Подпись сессии и шифрование токенов (AES-256-GCM). Пусто — создаётся в `data/.secret` |
| `APP_TIMEZONE` | Часовой пояс расписания и аналитики, по умолчанию `Europe/Moscow` |
| `DATA_DIR` | Папка с базой и видео, по умолчанию `./data` |
| `WORKER_ENABLED`, `CRON_SECRET` | Встроенный планировщик / внешний крон |
| `TIKTOK_CLIENT_KEY`, `TIKTOK_CLIENT_SECRET` | TikTok |
| `INSTAGRAM_APP_ID`, `INSTAGRAM_APP_SECRET`, `META_GRAPH_VERSION` | Instagram (по умолчанию Graph API `v26.0`) |
| `INSTAGRAM_UPLOAD` | `resumable` — загружать файл напрямую вместо скачивания по ссылке |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | YouTube |
| `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL` | ИИ-помощник (по умолчанию `claude-opus-5-5`) |

## Как устроено

```
app/
  (app)/                 страницы: обзор, контент-план, сценарий, календарь, аналитика, проекты, аккаунты, настройки
  api/upload             потоковая загрузка видео на диск (PUT, без буферизации в памяти)
  api/export             контент-план в CSV/TSV
  api/media, api/public  отдача файлов плееру (по сессии) и площадкам (по подписанной ссылке)
  api/oauth/[platform]   подключение аккаунтов
  api/cron               тик планировщика для внешнего крона
  actions.ts             серверные действия (паспорт, сценарии, импорт, публикации)
  ai-actions.ts          ИИ-помощник
lib/
  db.ts                  схема SQLite, миграции и доступ к данным
  plan.ts, planner.ts    правила шаблона: даты от старта, время, слова, статусы; перенос публикаций за планом
  tabular.ts, import.ts  разбор вставки/CSV, распознавание листов «Проекты» и контент-плана, импорт
  platforms/             адаптеры TikTok, Instagram, YouTube и демо-режим
  publisher.ts, worker.ts  очередь публикаций, повторы, обработка на площадках
  sync.ts                сбор статистики (частота зависит от возраста ролика) и импорт
  analytics.ts           снимки → дневные приросты, «×» к обычному, рубрики, тепловая карта
  insights.ts            правила рекомендаций
  demo.ts                демо-данные
instrumentation.ts       запуск планировщика вместе с сервером
proxy.ts                 проверка входа для страниц и API
```

Статистика обновляется: свежие ролики (до 2 суток) — раз в час, до недели — раз в 6 часов,
до месяца — раз в сутки, старше — раз в неделю.
